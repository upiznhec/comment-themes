# Instructions for AI agents

This repository sorts the comments on social media posts into themes (audience questions, objections, complaints, praise, requests, buying intent and more), with counts and exact quotes. The person sends post links; you read every comment of those posts, label the comments and write the report. The analysis follows `skills/comment-mining/SKILL.md` (adapted from ScrapeCreators' comment-mining, MIT). Scripts read the comments, count the labels and check the quotes.

Everything the person's data needs stays in `data/` (ignored by git): keys in `data/.env`, the person's remembered choices in `data/choices.json`, the comments in `data/comments.jsonl`, and one folder per request in `data/runs/`.

## Rules

1. **Talk to the person one thing at a time**, in plain words. Ask choices as questions (with your app's question tool if it has one). Ask only for what the current request needs, at the moment it is needed. Nothing is read, bought or changed without their OK. Steps for them to follow go in a message of their own, and you wait for their reply: do not open a question at the same time. A question box can cover the message above it (in a test it hid the list of which permission goes on which card, and the person asked twice). When they ask what is next, first check that the current step is done.
2. **Never ask for a key, token or password in the chat.** For a key they make, give them the one-line command that saves it (`node scripts/save-secret.js scrapecreators | youtube | x`, or `node scripts/meta-token.js` for Meta) to run in their own terminal. Ask them to run it first and, while it waits, to copy the key on its page and paste it at the prompt: then the key, not the command, is the last thing they copied (in a test the clipboard still held the command, and the command was pasted; the script now refuses a pasted command). Then run `node scripts/check-keys.js`, which shows whether each key works without showing it.
3. **Who does what.** Account steps, such as signing up, making a key or checking credit, happen in the browser the person always uses, where they are already signed in; never ask them to sign in again in a browser of yours. If you can work in that browser (for example their Chrome, through Claude's Chrome extension), open the pages and do the clicks yourself, and leave them only two things: signing in, and making and copying the key, which they then save with the command (rule 2). Section 4 says where that line is on each site. Passwords, payments and accepting terms are theirs too. While a key is on screen, do not read the page's text or take a screenshot. If you cannot work in their browser, say so in one sentence, so that they know why the clicks are theirs. Then open each page for them in their usual browser with the system's open command (`open "<link>"` on a Mac, `start "" "<link>"` on Windows, `xdg-open "<link>"` on Linux; it worked in DeepSeek Harness's sandbox), one page at a time, and tell them the one button to click on it, naming it as the page shows it. When a page has two buttons with the same name, say which one (for example, the Customize button on the card "Manage everything on your Page"), and give a direct link rather than a path through menus wherever you can.

   **Which account.** Before they sign in anywhere, tell them which account to use; section 4 says which on each site. In short, it is the account their posts belong to. A browser often opens another account first, such as a school or work account, so say it before the sign-in page appears; the warning about school or work accounts is for Google, not for Facebook or X.

   **Meta's sites** (Facebook, Instagram, Meta for Developers) are the exception: the person does every click, in the browser they always use. Start every message about a Meta step with the risk: Meta may log them out, ask for ID or restrict the account when a program clicks there; if that happens they stop and tell you. Never open these pages with your tools.
4. **Money**: before any read that costs money (ScrapeCreators credits, X credit), run `node scripts/fetch.js --run <name> --plan`, tell them what the full read costs, and wait for their OK. They buy credit themselves; never enter payment details.
5. **Numbers only from scripts.** Counts come from `tally.js` or `find.js`; never count or estimate comments yourself. Every quote in a report must pass `check-quotes.js`.
6. **Privacy**: commenters' shown names, handles and platform IDs are stored locally so the person can find and answer them. Leave names out of reports unless the person asks (for example, "list who asked about the price"). Pictures, gender and other profile data are never stored. Do not paste comments into other services.
7. **TikTok connector**: use only its reading tools (`account_user_get`, `account_user_post_list_get`, `account_user_comment_list_get`, `account_user_comment_reply_list_get`). Never reply, like, hide, delete or publish unless the person asks for that exact action in words.
8. **Do not assume anything is set up.** Do not take it for granted that the person already has any of these: keys, the TikTok connector, a Meta app and its permissions, a Facebook Page, an Instagram professional account. Before you rely on one, check that it exists and that it belongs to the account the posts are on. Whatever is missing, set up with them from the start, one step at a time. If you find something already there (a connector, an app, a Page or a token), tell them what it is and which account it belongs to before you use it. Never read a different post, Page or account from the one they sent unless they ask you to.

## Setting up

When the person asks you to set this up, download the repository (with git, or as a ZIP if git is not available) and run `npm test` to check that Node.js 20 or newer works. Then tell them in two or three sentences how to use it: send the links of the posts whose comments they want sorted (YouTube, Instagram, Facebook, TikTok, X or Reddit), and say which posts are their own. Ask nothing else now: routes and keys are settled the first time a request needs them. If the setup message already contains a request, go on with it.

## Each request

### 1. Write the request
Give the request a name (letters, digits, dots and dashes, such as `2026-11-21-launch`) and write its links to `data/runs/<name>/request.json`:

```json
{
  "posts": [
    { "url": "https://www.instagram.com/p/POST_CODE/", "own": true },
    { "url": "https://www.tiktok.com/@anotherbrand/video/VIDEO_ID", "own": false },
    { "url": "https://www.youtube.com/watch?v=VIDEO_ID" }
  ]
}
```

- Copy each link exactly as the person sent it, and compare the file with their message afterwards. Long numbers in X, TikTok and Facebook links are easy to change by one digit: in a test, an X link was written with its last digit changed, and X answered "not found".
- `"own"` says whether the post is the person's own. It is required for Instagram, Facebook and TikTok links, because it decides how the post is read; if the person did not say, ask. Posts from accounts listed under `own_accounts` in `data/choices.json` are theirs.
- Every comment of each post is read; there is no time window. If the person wants an account's latest posts, ask them for the links.
- A post may carry `"route"` to override the remembered choice, for example `"scrapecreators"` for a post on their personal Facebook profile when their choice for Facebook is the official route, which reads only Pages (business accounts).

### 2. How each post is read

| Platform | The person's own post | Someone else's post |
|---|---|---|
| YouTube | Official API (free, key) | Official API |
| Instagram | Official API (free; needs their own Meta app; gives names) or ScrapeCreators | ScrapeCreators |
| Facebook Page (a business account) | Official API (free; while the Meta app is in development mode it gives other people's comments **without who wrote them**) or ScrapeCreators (gives names) | ScrapeCreators |
| Facebook personal profile, also one in professional mode | ScrapeCreators only (the official API reads Pages, not profiles) | ScrapeCreators |
| TikTok | The official TikTok Social connector (free; works with personal accounts) or ScrapeCreators | ScrapeCreators |
| X | Official API (paid credit) | Official API |
| Reddit | ScrapeCreators | ScrapeCreators |
| Any | Paste comments or import a CSV (`scripts/import.js`) | same |

The first time the person sends their own Instagram, Facebook or TikTok post, explain the two routes for that platform (official: more setup, free, their own posts only; ScrapeCreators: one key, costs credits, also reads other people's posts) and let them choose. The official route has conditions: on Facebook the post must be on a Page (a business account) that they manage, and on Instagram on a professional account linked to that Page. Before offering it, check these with them as section 4 says (Meta, step 1), even when they call the account their Page. Save the choice, and any account they say is theirs, in `data/choices.json`, and do not ask again:

```json
{
  "own_routes": { "instagram": "official", "facebook": "scrapecreators", "tiktok": "mcp" },
  "own_accounts": ["Instagram @yourbrand", "TikTok @yourbrand"]
}
```

If they later ask to read their own posts on a platform another way, change `own_routes` in `data/choices.json` and set up only what the new route needs (section 4).

### 3. Check what is missing, then agree the cost
Run `node scripts/fetch.js --run <name> --plan`. It lists each post with its number of comments, where the platform gives one, and what reading it costs (the plan itself is free, except about $0.005 for looking up each X post). It also names what is still missing:
- "ask whether this ... post is the person's own" or "ask how to read the person's own ... posts": ask, update `request.json` or `choices.json`, and run the plan again.
- "key not saved yet": set up that key only (section 4), run `node scripts/check-keys.js`, and run the plan again.

Then tell them the cost (rule 4) and, with their OK, run `node scripts/fetch.js --run <name>`.

Reading takes time: ScrapeCreators answers about one page every 4 seconds (in a test, 156 pages took 11 minutes); YouTube and X are quicker. Before a read of more than about 50 pages, tell the person roughly how long it will take. If your app can run it in the background, do so, and tell them as each platform finishes; fetch.js prints a line as each post starts and every 10 pages, so its output shows how far it has got.

### 4. Keys and connections, only the ones a request needs
Do not assume they have any of these yet (rule 8). Before the first step for a key, tell them in a sentence or two what it is for, whether it costs anything, which account to sign in with, and how the work is split (rule 3): you open the pages and do the clicks; they sign in, then make and copy the key and save it with the command. When you hand a step over, say on which page and under which button it is and what they should see. When the next step shows a key, give the save command first (rule 2): they run it, then copy the key while it waits.

- **ScrapeCreators** (100 free credits, no card; credits never expire; 1 credit per page of comments, about 10 to 20 comments): open https://scrapecreators.com in their browser, and they sign up or log in, with any email address they like. Then open the dashboard page that shows the API key and stop there: they copy the key and save it with `node scripts/save-secret.js scrapecreators`.
- **YouTube** (free: 10,000 units a day, and 1 unit reads up to 100 comments; no billing account or card): in their browser, open https://console.cloud.google.com/ with a personal Google account; for their own videos, suggest the one of their YouTube channel. Not a school or work account: its administrators may not allow Google Cloud, and it may send them to their organisation's sign-in page (in a test, Chrome opened a university's). The key reads any public video, so it does not have to be the channel's account. They sign in if it asks; if the browser has more than one account, ask which. Choose a project or create one, for example "Comment themes"; open https://console.cloud.google.com/apis/library/youtube.googleapis.com and click Enable; then open https://console.cloud.google.com/apis/credentials and stop there. They click Create credentials, then API key, choose YouTube Data API v3 under API restrictions if the form offers it, copy the key and save it with `node scripts/save-secret.js youtube`. If Google offers a free trial or asks for a card, skip it.
- **X** (paid from credit): open https://console.x.com in their browser, and they sign in with their own X account. Look at their credit balance: with none, X refuses to read, so they buy some themselves (no automatic top-ups; never enter payment details); the plan gives the cost once the key is saved. Then open the page where apps are made and stop there: they create a **new** app, which shows its Bearer Token once, copy the token and save it with `node scripts/save-secret.js x`. Never ask them to press Generate or Regenerate on an app they already have: it stops whatever uses the old token. If the console allows no more apps (in testing, 3 in a project), stop and let them choose an app they no longer use to delete, or leave X out. Posts of any age can be read: replies to posts older than 7 days come from full-archive search, which pay-per-use accounts (credit bought at console.x.com) include. If X refuses it, fetch.js skips those posts and gives X's reason.
- **Meta (Instagram and Facebook official)**: free, through their own Meta app in development mode (no App Review). They do every click (rule 3), signed in to Facebook with the profile that manages the Page the posts are on. Do not assume any of the following exists yet: check each one, and finish each step before the next:
  1. **What the posts are on.** On Facebook the official route reads only posts made by a Facebook Page (a business account) that their profile manages. A personal profile cannot be read this way, even in professional mode: a "Digital creator" label and a Dashboard button do not make it a Page. Ask them to open https://www.facebook.com/pages/?category=your_pages and say whether the account that made the post is listed there.
     - Listed: go on.
     - A Page that another Facebook profile manages: that profile does every step below.
     - Their personal profile: tell them plainly that the official route cannot read this post, and offer ScrapeCreators for it (or pasting the comments). If they want the official route for later posts, explain that it needs a Page, which they can make at https://www.facebook.com/pages/create and post from; posts already on the profile stay out of its reach. Guide them through making the Page, one step at a time, only if they choose it.

     On Instagram, the official route reads the posts of an Instagram professional account (Business or Creator) linked to that Page. Check it in one step, which works on a computer: on Facebook they switch into the Page, then Settings, Linked accounts. An Instagram account shown there as connected is always a professional one, so nothing else needs checking. Only if none is connected: ask whether they are on a computer or a phone before giving app steps (in a test, steps for the phone app went to someone on a computer, and Instagram's website does not show the account type). A personal account is switched in the Instagram phone app (their profile, the menu, Settings and activity, Account type and tools, Switch to professional account); then they connect it on that Linked accounts page with Connect account. Menus change: if theirs differ, ask what they see (a screenshot helps).
  2. **The app.** At https://developers.facebook.com/apps they click Create app, give it a name (for example "Comment themes") and choose the use case "Manage messaging & content on Instagram"; asked about a business portfolio, they choose "I don't want to connect a business portfolio yet". Do not ask them for the app ID, or anything else about the app, in the chat: they type the app ID only into meta-token.js (step 5), which then shows the link to the page with the app secret.
  3. **Permissions.** In the app's left menu they click Use cases (the third item, under Dashboard and Required actions). It must show two cards, "Manage messaging & content on Instagram" and "Manage everything on your Page"; if one is missing, they add it with "Add use cases". On each card they click that card's own Customize, then Permissions and features, and Add next to each of these that is not added yet (name the card each time):
     - on the Instagram card: `instagram_basic` and `instagram_manage_comments`;
     - on the Page card: `pages_read_engagement`, `pages_read_user_content` and the feature "Business Asset User Profile Access".

     `pages_show_list` and `business_management` were already there in testing; if step 4 does not offer them, add them the same way. Add nothing else from these lists. Two things they may see (seen in a test): on the Instagram card, a banner saying a business portfolio is mandatory for the "Unified login" setup, which they can leave alone (the token comes from Graph API Explorer through Facebook login); and, when adding a permission, a box saying it "will affect other use cases on this app", where they click Add (the same permission is then added to the other card too).
  4. **The token.** At https://developers.facebook.com/tools/explorer/ they choose the app under Meta App, then tick all six under Add a Permission: `instagram_basic`, `instagram_manage_comments`, `pages_show_list`, `pages_read_engagement`, `pages_read_user_content`, `business_management`. A permission missing from that list was not added in step 3 (in a test, `pages_read_engagement` was missing until it was added). Then they click Generate Access Token and, in the pop-up, choose the Page the posts are on and its Instagram account.
  5. **Saving it.** Before giving the command, tell them where the two values are, since they will be asked for them: the app ID is the number after `/apps/` in the address bar (also on App settings, Basic), and the app secret is on App settings, Basic, behind Show (in a test the person asked for this before starting). They run `node scripts/meta-token.js`. It asks for the app ID (the number after `/apps/` in the address bar of any page of the app), then shows the link to the page with the app secret (App settings, Basic: Show next to App secret), and asks for the secret and the Explorer token. It saves a Page token that does not expire. Then run `node scripts/check-keys.js`: the Page and the Instagram account it names must be the ones the posts are on.
- **TikTok Social connector** (official and free, https://business-api.tiktok.com/open_mcp/tt-ads-mcp-organic-social): no developer account or app. Do not assume they have added it (rule 8): first check whether its tools work for you (`account_user_get`). If not, walk them through adding it to your own app, one step at a time, following your app's current documentation for remote MCP servers (connectors); TikTok lists ChatGPT, Claude, Claude Code, Codex, Cursor, Gemini CLI and others. In Claude it is in the connector directory as "Tiktok Social" (not "TikTok for Business", which is for ads): Settings, Connectors, Browse connectors, then Connect; adding it as a custom connector with the URL above also works. When TikTok's page opens, they sign in with the TikTok account that posted the videos and authorize; the authorization lasts a year. In Claude it must then be switched on for the chat (the chat's + menu, Connectors). Once it works, call `account_user_get` and check that its username is the one in the video links: the connector reads only that account's videos.

  If your app cannot add it, or cannot do its sign-in (in DeepSeek Harness, as of the test, an MCP server takes only a link and fixed headers, with no sign-in step), use `node scripts/tiktok-bridge.js`. It runs the same connector through mcp-remote (a small MIT program from npm, pinned to one version and downloaded by npx the first time), calls only the four reading tools and keeps the sign-in in `data/tiktok-auth/`. Tell them first, in a sentence, that it downloads that program and that TikTok's sign-in page will open in their browser. Run `node scripts/tiktok-bridge.js --check`: they sign in with the TikTok account that posted the videos and allow access, and it prints the account; check it against the video links. If your app cannot open their browser, the script prints the sign-in link for them to open. If neither way works, say so and offer ScrapeCreators for their TikTok.

### 5. Their own TikTok videos through the connector
fetch.js only lists them. With the bridge (section 4), `node scripts/tiktok-bridge.js --run <name>` does everything below for every own TikTok video of the request: it reads the comments and replies, keeps TikTok's answers in the run folder, imports them and keeps each video's own text. With the connector in your app, do it yourself. First call `account_user_post_list_get` (`fields: ["item_id", "caption", "comments", "create_time"]`, `filters: { "video_ids": ["<video ID>"] }`, `max_count: 1`), save the answer as `data/runs/<name>/tiktok-<video_id>-post.json` and run `node scripts/import.js --tiktok-mcp <file> --post <the link> --run <name>`: it keeps the video's caption for the analysis (in a test, the agent could not tell what a video was about until it looked the caption up). Then, for each video, take the video ID from the link (the digits after `/video/`), call `account_user_comment_list_get` (`video_id`, `include_replies: true`, `max_count: 30`) and pass `cursor` until `has_more` is false. Each comment comes with at most three replies; for a comment whose `replies` number is higher, call `account_user_comment_reply_list_get` (`video_id`, `comment_id`, `max_count: 30`) the same way. Save each answer as it came to `data/runs/<name>/tiktok-<video_id>-<page>.json` (replies: `tiktok-<video_id>-<comment_id>-<page>.json`) and run `node scripts/import.js --tiktok-mcp <file> --post <the link as written in request.json>` for each file. The import removes the profile picture links from the file.

### 6. Facebook links the official route cannot match
A share link to a post of their Page (`pfbid...` or `/share/...`) is looked for among the Page's posts. If it is not found, fetch.js lists the Page's latest posts with their dates and first words. First make sure the post is on this Page at all (section 4, Meta, step 1): a post on a personal profile or on another Page cannot be read with this token, and then you do not offer this Page's posts in its place. If it is on this Page, ask which of the listed posts it is, and put that post's link in `request.json` instead.

### 7. The analysis
1. `node scripts/prepare.js --run <name>`. It takes the comments of the request's posts and names any post with no comments stored (not read yet, nothing to read, or skipped). A post with more than 1,000 comments is analysed on its 1,000 most-liked (the same limit per post as ScrapeCreators' YouTube comments endpoint, which returns at most about 1,000 top comments a video); every comment of the other posts is included. Before labelling, tell the person how many comments you will label. Use `--all` only if they ask to label every comment, after telling them it uses many more tokens (about 15 tokens of text per comment, before the labels). It also prints what each post says itself (its caption, title or text, kept in `posts.json` when fetch.js read it): read it before labelling, so you know what the comments answer, and say in the report's summary what each post is about. Posts read through the TikTok connector, pasted or imported have no saved text; ask the person what the post is about if the comments do not make it clear.
2. Label every batch as `skills/comment-mining/SKILL.md` says, into `data/runs/<name>/labels.jsonl` (or one file per batch, `labels-01.jsonl` and so on). With more than one batch, keep the themes you use in `data/runs/<name>/themes.md`, one line each under its bucket, and reuse them word for word in later batches. To merge two themes, change the theme in every labels file and in `themes.md`, then tally again.
3. `node scripts/tally.js --run <name>` until it reports no problems.
4. Write `data/runs/<name>/report.md` in the skill's format, with numbers from `summary.json` only and comment IDs after quotes. Put only words from the comments in double quotes or `>` lines: `check-quotes.js` checks every such text of 6 characters or more, so write names and titles (a Page's name, a video's title) without quotes. If `summary.json` has a sample, say in the summary which posts were cut to their 1,000 most-liked comments (with how many each had); counts for those posts lean towards their most popular comments.
5. `node scripts/check-quotes.js --run <name>`; fix every quote it does not find.
6. Tell them where the report and `labelled.csv` (every comment with its bucket and theme, to check or filter) are, and the main points in a few lines. Then give two or three examples of questions they can ask you, such as "How many people asked about the price?" or "Show me every complaint about shipping".

To analyse everything read so far, or a part of it, use a new run name without a `request.json`: `prepare.js --run <name>` then takes the whole database, narrowed by `--days`, `--since`, `--platform`, `--post <part of a link>` or `--own`/`--others`.

## The person's own questions

Answer from the database with `node scripts/find.js`: `--text "words"`, `--platform`, `--post <part of a link>`, `--days`, `--own`/`--others`, `--run <name> --bucket <bucket>` or `--theme <words>`, `--count` for numbers only, `--names` only when they want to know who. Give the counts it prints and quote with the IDs it shows. To refresh a request's comments first, run `fetch.js --run <name>` again (and the TikTok steps); comments already stored are updated, not repeated.

## Known limits (tested 2026-11-21)

- YouTube: at most 5 replies come with each comment; the rest cost 1 more unit per 100 (read by default; `--no-replies` skips them). Videos with comments turned off are skipped with a note.
- Instagram official: reads only posts of the Instagram account linked to the person's Page.
- Facebook official, development mode: other people's comments come without name or ID (the comment written as the Page itself has them). The official route reads only Pages (business accounts); a personal profile, also one in professional mode, cannot be read this way.
- Large posts: at most `--max-pages` pages of comments are read per post (default 30: up to 3,000 comment threads on YouTube, about 300 to 500 comments through ScrapeCreators). The plan says when a post has more. Such posts are read top comments first on YouTube and most relevant first on X; ScrapeCreators returns comments in the order it gets them from the platform. With the TikTok connector, for a video with more than 900 comments use `sort_field: "likes"`, `sort_order: "desc"` and stop after 30 pages. YouTube allows 10,000 free units a day; a bigger read stops when they run out, and running it again the next day continues.
- Large analyses: a post with more than 1,000 comments is labelled on its 1,000 most-liked (see "The analysis"). The person's own questions (`find.js`) still count over every comment read, which costs no tokens for labels.
- ScrapeCreators: the number of comments is not known before reading, so the plan gives a ceiling (at most `--max-pages` credits per post, plus 1 for the post's own text and comment count on Instagram, TikTok and Facebook; Reddit's come with the comments). Instagram succeeds about 9 times in 10 (ScrapeCreators' own figure); Instagram, TikTok and Facebook replies are not read (their count is kept); Reddit's comment count includes removed comments, so fewer come back.
- TikTok connector: beyond 500 comments on one video, TikTok returns the rest by likes and may repeat some; the database keeps one copy of each.
- X: looking a post up costs about $0.005, each reply $0.005 and each different replier $0.010. The reply count X shows is of direct replies only; replies to replies are read too, so a thread can cost more than the plan's figure (in a test, a post showing 6 replies had 11). X does not charge again for a post or user read earlier the same UTC day (X calls this a soft guarantee). Replies to posts from the last 7 days come from recent search; replies to older posts come from full-archive search, which allows 1 request a second and 300 in 15 minutes (fetch.js waits between requests). If X answers HTTP 429 (too many requests), wait 15 minutes, then read only the posts that stopped with `fetch.js --run <name> --post <link>`; the other posts are already stored.

## Updating it

With git, run `git pull`; `data/` is not touched. Without git, download the new version into a new folder and copy `data/` into it, then ask before deleting the old folder. Run `npm test` afterwards, and `node scripts/check-keys.js` if they want to know their keys still work.

## Removing it

Ask before deleting anything. To remove the data, delete the `data/` folder (keys, choices, comments and analyses). Keys can also be removed at each provider: the ScrapeCreators dashboard, Google Cloud Credentials, the X Developer Console, and for Meta, Facebook Settings, Business integrations; the TikTok connector in the app's connector settings (with the bridge, its sign-in is in `data/tiktok-auth/` and goes with `data/`).
